# 0. Overview
This posts walk you through how to bring your organisation key to Azure to replace the tenant root key.
Regarding Azure Information Protection, the AES key created when the document encrypted by the tenant root key(Public).
By default, this key is managed by Microsoft. But you can also use your own key that created and managed by your organisation.

The following document walk you through how you can import your own key and replace the default key with your own key.

ref)
<https://learn.microsoft.com/en-us/purview/rights-management-how-does-it-work>
<https://techcommunity.microsoft.com/blog/microsoft-security-blog/understanding-microsoft-information-protection-encryption-key-types/2214589>

# 4. Import the AD CS Key
1. Before the execution command to import the key, we need to get the proper permission. 
From the KeyVault > IAM > Check access > Grant access to this resource > Add role assignment, we need "Key Vault Crypto Officer" role.
<img width="1920" height="1152" alt="2026-09-12 20 11 50" src="https://github.com/user-attachments/assets/d818ddb5-0916-47b3-a702-54f4bb26d159" />

2. After that, import the pfx using the command
```powershell
$PfxPassword = Read-Host "PFX Password" -AsSecureString
$Key = Add-AzKeyVaultKey -VaultName "KeyVault-notnull" -Name "EntraIdBYOK" -KeyFilePath "C:\temp\EntraIdBYOK.pfx" -KeyFilePassword $PfxPassword
$Key
```

# 5. Preparing RMS from the az shell
ref: <https://learn.microsoft.com/en-us/purview/rights-management-byok>
1. Open the az shell and select your subscription.
```shell
az login
```
<img width="1920" height="1152" alt="2026-09-12 20 18 54" src="https://github.com/user-attachments/assets/5aecff0a-c343-488d-87dd-d614675ef93b" />

2. Specify the Keyvault
```shell
az keyvault show --name <vault-name> --resource-group <resource-group-name> --query "id" -o tsv
```
<img width="1920" height="1152" alt="2026-09-12 20 19 17" src="https://github.com/user-attachments/assets/3b6a3c8b-b18e-47e0-8778-7d6c68e3ad03" />

3. Create the json that define the RMS role regarding the key vault
```shell
# touch PurviewRMSCustomAKVRole.json
# nano PurviewRMSCustomAKVRole.json
# cat PurviewRMSCustomAKVRole.json
{
  "Name": "Purview Rights Management key vault Encryption User",
  "IsCustom": true,
  "Description": "Grants access to use key vault keys for the Purview Rights Management service.",
  "Actions": [],
  "NotActions": [],
  "DataActions": [
    "Microsoft.KeyVault/vaults/keys/read",
    "Microsoft.KeyVault/vaults/keys/sign/action",
    "Microsoft.KeyVault/vaults/keys/decrypt/action"
  ],
  "NotDataActions": [],
  "AssignableScopes": [
    "/subscriptions/<subscription-id>"
  ]
}
```
<img width="1920" height="1152" alt="2026-09-12 20 21 28" src="https://github.com/user-attachments/assets/6caad55a-2505-4a1f-8cbd-b40ea358c42a" />

4. Create the role with the json.
```shell
az role definition create --role-definition "./PurviewRMSCustomAKVRole.json"
```
<img width="1920" height="1152" alt="2026-09-12 20 22 09" src="https://github.com/user-attachments/assets/89bcd11a-e67b-482c-9611-121e7d526c12" />

5. In this case, I made the Service principal(RMS) because I didn't get E5 license and Purview yet.
```shell
az ad sp create --id 00000012-0000-0000-c000-000000000000
```

```shell
az role assignment create --role "Purview Rights Management key vault Encryption User" --assignee "00000012-0000-0000-c000-000000000000" --scope $(az keyvault show --name <vault-name> --resource-group <resource-group-name> --query "id" -o tsv)
```

# 6. Assign the KEY to AIP Service
This is the last part of this configuration.

1. Connect AIPService Shell.
```powershell
Get-AipServiceKeys
```
<img width="1025" height="770" alt="2026-09-12 21 20 38" src="https://github.com/user-attachments/assets/48357678-4b37-4c04-93ec-0564c50205f1" />

2. Declare to use the key from the KeyVault.
```powershell
Use-AipServiceKeyVaultKey -KeyVaultKeyUrl "https://contosorms-kv.vault.azure.net/keys/contosorms-byok/<key-version>"
```
<img width="1348" height="641" alt="2026-09-12 21 32 08" src="https://github.com/user-attachments/assets/9f8d296f-93f8-4e42-a971-ead2022e83e2" />

3. Make our key as primary(Active)
You can see the Microsoft managed key set as archive.
You can't delete this key. Because it literally managed by Microsoft even if we import our own key.
```powershell
Set-AipServiceKeyProperties -KeyIdentifier <key-id-from-previous-step> -Active $true
Get-AipServiceKeys
```

# 8. Warning
If you disable the own key or delete the key from the Azure, the end user will not open the encrypted document.
Because the key is used for decrypt the content key which is encrypted by our own key.
So, it may be considered set as "archive" when you need to change new key.
